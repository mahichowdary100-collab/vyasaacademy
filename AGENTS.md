## Content overrides

- Authorable content lives at `cbse-study-material\content\class-<N>\<subject>\<chapter-slug>\<resource-slug>\index.html`.
- If an override exists, `_build.ps1` (function `Get-ContentOverride`) emits it verbatim; otherwise it emits a noindex placeholder stub.
  Creating a real resource means adding the override, then rebuilding.
- After add/change: rebuild, SHA-compare built output to the override (must be identical), link-walk, update `sitemap.xml` (root; alphabetical) and `indexable-urls.txt` (built by `_build.ps1`) as needed, deploy, then live-verify.

## Reusable architecture

- Reuse existing templates rather than building new frameworks:
  - Notes/practice-paper/quiz/test templates are the authored versions under `content\class-10\mathematics\real-numbers\` and `...\polynomials\`
- Quiz/test data model: a `QUESTIONS` array with fields `id, section, type (mcq|ar|subjective), marks, difficulty, competency, topic, sourceType, sourceYear, sourceExam, isApplication, isCompetency, isGraphBased, isHOTS, isCaseBased, q, options, answer, concept, solution` plus a `SECTIONS` array, `TOTAL`, and `TIME_LIMIT`.
- Timer early warnings list seconds (e.g. `900, 300, 120, 60`) and auto-submits at 0.
- MCQ/AR auto-scored; subjective self-assessed via a mark-awarding `<select>` against model solutions in review view.

## Content rules

Do not invent CBSE PYQs. A question may be labelled PYQ only when its source is verified. If source cannot be verified:

> "Original — CBSE Exam-Style"

Never fabricate:

- examination year
- question number
- paper set
- paper code
- CBSE source

### PYQ attribution (strict)

- Only mark a question as a PYQ when the year + paper code are genuinely verified.
  Example: `sourceType: "CBSE PYQ"`, `sourceYear: "2024"`, `sourceExam: "CBSE Board Paper 2024 (Mathematics Standard, Paper 30/1/1)"`.
- Attribution is paper code only - never paste question-set numbers unless confirmed; never invent year/paper/session.
- Original items: `sourceType: "Original"`, `sourceYear: null`, `sourceExam: null`.

## Mathematics

All mathematical content must be checked carefully. Use MathJax or KaTeX where already supported.

Check:

- formulas
- signs
- calculations
- answer keys
- solutions
- marks
- question totals

### Authoring conventions

- JS object/string values use double quotes. Avoid apostrophes inside single-quoted JS strings.
- Rupees as `&#8377;` (never literal `₹`).
- MathJax inline delimiters `\(...\)`; keep them balanced.
- No Liquid and no `noindex` in override files (the placeholder stub of an unbuilt resource is what carries noindex).
- Inline charts as `<svg>` with `role="img"` + `aria-label`; axis lines use class `ct-axis`, data lines `ct-curve`, origin markers `ct-zero`, labels `ct-lab`.
- PowerShell validation scripts must be ASCII-only (PowerShell 5.1 reads .ps1 as ANSI).

## Validation checklist (per new resource)

- Exactly the spec'd total marks; section marks sum to the total; exact question counts per section.
- Every MCQ has exactly 4 options and its `answer` in 0-3; every AR answer in 0-3; subjective `options/answer` null.
- No duplicate questions or contradictory answer keys; all numerical/algebraic/graph/case answers correct.
- MathJax delimiters balanced; no broken internal links (link walk); PYQ metadata verified only.
- Subject scope respected (e.g. tests must not require out-of-syllabus methods like cross-multiplication).
